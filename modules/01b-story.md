# 模块 01b · 故事与设定（story & world）

> **v2 新增。** 与模块 01 是同一阶段（P0 立项）的两个产物：
> 01 写「怎么玩」，01b 写「为什么玩」。两者都必须完成才能过 RC 丰富度门禁。

---

## 目标

产出一份**能驱动关卡与代码**的叙事规格，而不是一段世界观散文。

判断标准：把 `story.md` 给一个没参与设计的人看，他能答出三个问题——
① 主角为什么必须做这件事 ② 玩到一半会发生什么变化 ③ 结局为什么这么收。

---

## 输入

- `.gamedev/state.yaml` 里的 `idea`（一句话）
- `docs/01-brief/analysis.json`（`content_forge.py --analyze` 的推荐框架与机制池）
- `docs/01-brief/content-blueprint.json` 骨架

## 步骤

### 1. 选框架（不要跳过）

`assets/data/story-frames.json` 有 8 个框架，每个都验证过"适合小游戏"。
**先选框架再写内容**，因为框架决定了三幕的结构，结构错了内容再好也散。

| 框架 | 最配的品类 | 一句话 |
|---|---|---|
| `cycle_curse` 循环诅咒 | roguelite / arcade | 一直重来，只有你记得 |
| `descend_layers` 逐层深入 | tower_defense / survival | 越深越危险，也越接近真相 |
| `collect_truth` 收集真相 | puzzle / management | 碎片拼起来才知道发生过什么 |
| `guard_lose` 守护与失去 | tower_defense / survival | 你守的东西一定会失去 |
| `absurd_work` 荒诞职场 | management / idle | 公司规则没人解释过 |
| `anthropomorph_daily` 拟人日常 | whack / puzzle | 天亮就忘光 |
| `bargain_debt` 交易与代价 | roguelite / card | 变强要付代价 |
| `reverse_story` 反向叙事 | puzzle / card | 从结局往回打 |

选错框架的典型症状：写完了但"每关都一样"。那不是内容问题，是结构问题。

### 2. 写世界规则（最容易写歪的一节）

规则必须是**约束**，能推出玩法。检验方法：每条规则后面加一句"所以玩家必须…"。

| 不合格 | 合格 |
|---|---|
| 这里很神秘 | 这片海面在月亮升起后不再反射任何光 → 所以玩家只能靠灯判断敌人位置 |
| 灯塔很重要 | 灯塔的光是一种货币，点亮一次就少一分 → 所以玩家要决定什么时候亮 |
| 主角很孤独 | 主角每夜都要和灯说话，灯会回一句 → 所以对白是玩法的一部分 |

3 条规则里，**至少 1 条要直接决定资源或信息**，否则它只是氛围。

### 3. 主角：want ≠ need

| 字段 | 含义 | 例子 |
|---|---|---|
| `want` | 表层想要（玩家前 3 关的目标） | 把灯守住，不让它灭 |
| `need` | 真正需要（玩家最后才明白） | 承认自己守的不是灯，是三十年前没能救的人 |
| `flaw` | 阻碍他得到 need 的东西 | 不肯承认失败，所以从不敢让灯灭一次 |
| `arc` | 从 → 到 | 从"必须守住"到"允许它灭掉" |

**want 与 need 相同 = 没有弧光**，`--validate` 会直接报错。

### 4. 三幕：每幕必须有 turn

| 幕 | 占关卡 | 该做什么 |
|---|---|---|
| 一 | 第 1–2 关 | 建立常态 + 教会核心机制。turn = 第一次出现"不对劲" |
| 二 | 中段 | 机制叠加、压力上升。turn = **规则被改写**（对应 `mechanics.rule_twist`） |
| 三 | 最后 1–2 关 | 用全部机制面对最终压力。turn = 代价兑现 |

**turn 为空的三幕等于没有三幕。** 只写 goal 就是"打怪、打更多怪、打完"。

### 5. 每关一句 logline

格式：`第 N 关：<发生什么>，<玩家的处境变化>`

- ✅ `第 4 关：潮水第一次越过堤岸，你能点的格子少了三分之一`
- ❌ `第 4 关：难度提升`

logline 会直接变成关卡选择界面的文案，所以它得是**给玩家看的**，不是给开发看的。

### 6. 对白：只写推动认知的话

硬约束（`content-depth.md` §3）：
- 12–20 条
- 单条 ≤40 字（约 3 秒配音）
- 每条必须有 `cue`，且 cue 能对上真实关卡事件

**cue 规范**：`lv<N>_start` / `lv<N>_end` / `lv<N>_twist` / `win` / `lose` / `menu_idle`

三类该写的台词：

| 类型 | 作用 | 例子 |
|---|---|---|
| **规则台词** | 用世界观解释机制 | "灯照到的地方，它们不敢上来。"（= 光照范围就是防御范围） |
| **代价台词** | 说明这一关失去了什么 | "第三根柱子也塌了。"（= 可选格子减少） |
| **转折台词** | 改写玩家理解 | "你以为你在守灯。灯在守你。" |

**不该写的**：寒暄、感叹、背景介绍长句、任何删掉不影响理解的话。

### 7. 结局：必须有代价或获得

`ending_beats` ≥2 个节拍，且不能是"循环继续"。
开放式收尾在小游戏里等于"没做完"——玩家会觉得被耍了。

## 自检

- [ ] `content_forge.py --validate` 无 ERROR
- [ ] 3 条世界规则，每条能推出一个玩法约束
- [ ] want ≠ need，arc 是"从 X 到 Y"
- [ ] 三幕的 turn 都不是空
- [ ] 每关 logline 是给玩家看的句子，不是难度描述
- [ ] 对白 ≥12 条，每条 cue 能对上关卡事件
- [ ] 结局有明确代价或获得
- [ ] **故事解释规则为什么是这样**（不是贴上去的皮）

---

## 常见错误

| 错误 | 症状 | 修法 |
|---|---|---|
| 故事与玩法脱钩 | 删掉所有对白游戏照样玩 | 让每条世界规则都约束一个机制（§2） |
| 写成 AVG | 对白 40 条、过场 6 张 | 砍到 20 条以内，单条 ≤2 行 |
| 三幕没有 turn | 玩家感觉"一直在打同一种怪" | turn 必须是规则变化，不是数量变化 |
| 主角没有缺陷 | 玩家没有代入感，输了只觉得手慢 | flaw 要能被玩法惩罚（例：不敢让灯灭 → 不敢用大招） |
| logline 写成设计注释 | 关卡界面显示"难度提升" | 改写成玩家视角的一句话 |
