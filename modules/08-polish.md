# 模块 08 · 打磨（polish）

**阶段**：P3 ｜ **前置**：P2 全部完成 ｜ **产出**：优化后的 `src/`、`docs/05-polish/juice-log.md`

## 目标

把「能玩」变成「玩起来舒服」。接入正式素材、补齐 UI、加手感反馈、落难度曲线。

## 步骤

### 1. 接入正式素材

- 用 `assets/atlas/` 替换 `04-core-loop` 阶段的几何占位
- 保留 `src/game/config.ts` 中的尺寸参数，改为读取图集帧的实际尺寸
- 替换后完整回归一遍 L1 检查项（防止引入回归）

### 2. 补齐 UI

至少包含：开始界面、HUD（分数/进度）、暂停、结束界面、重开按钮。

**要求**：
- UI 元素全部来自图集，不出现代码绘制的临时方块
- 移动端触摸目标 ≥44×44 px
- 字号在 320px 宽视口下仍可读

### 3. 加 juice（手感反馈）

`docs/05-polish/juice-log.md` 中逐条记录加了什么、参数是多少。至少落地两项：

| 手段 | 示例 |
|---|---|
| 屏震 | 合成成功时 `camera.shake(80, 0.004)` |
| 缓动 | 元素出现/消失用 `Back.easeOut` 而非线性 |
| 粒子 | 合成时爆出碎屑粒子 |
| 缩放反馈 | 命中瞬间 `scale 1 → 1.15 → 1` 回弹 |
| 音效反馈 | 每个关键动作都有对应 SFX |
| 数字跳动 | 分数变化时滚动而非瞬变 |

**原则**：反馈必须在 **100ms 内**发生，否则玩家感觉不到因果。

### 4. 落难度曲线

按 GDD 实现难度递增（生成概率、速度、间隔等），并把参数集中到 `config.ts` 的难度表里，便于后续调整。

### 5. 存档

- 最高分 / 进度通过 `platform.save()` / `load()` 持久化
- 首次进入无存档时必须优雅处理（不报错）
- 存档结构加版本号，便于后续迁移

### 6. 移动端适配

- 触摸操作可用
- 视口按 `scope.json` 的 `orientation` 配置
- 安全区域留白（CrazyGames App 全屏时有 safe area）
- `body` 的 `user-select: none` 已生效（长按不弹出选择菜单）

### 7. 校验

```bash
python <skill>/scripts/gate_check.py --project <project> --stage polish
```

## 自检

- [ ] 正式素材全部接入，无残留占位方块
- [ ] UI 完整：开始 / HUD / 暂停 / 结束 / 重开
- [ ] juice 至少两项，且有 `juice-log.md` 记录
- [ ] 难度曲线与 GDD 一致
- [ ] 存档可用，刷新后保留，首次进入不报错
- [ ] 移动端触摸可玩，安全区域留白
- [ ] 回归 L1 全部检查项通过

## 常见错误

| 错误 | 后果 | 纠正 |
|---|---|---|
| 换素材后没回归测试 | 引入回归缺陷 | 每次替换后跑一遍 L1 |
| 反馈延迟 >100ms | 手感迟钝 | 检查事件链路是否经过异步 |
| 存档无版本号 | 后续改结构会崩 | 加 `version` 字段 |
| 只做桌面端适配 | 丧失移动端流量 | 移动端是 CrazyGames 首页流量的关键 |
