# 模块 10 · 测试与试玩（qa）

**阶段**：P4 ｜ **前置**：`09-perf-audit` 通过 ｜ **产出**：`docs/07-qa/report.html`、试玩链接

## 目标

用浏览器自动化跑一遍完整走查，产出可视化报告与可分享的试玩链接。

## 步骤

### 1. 启动预览

```bash
cd <project> && npm run build:cg && npx serve dist/crazygames -l 5173
```

### 2. 自动化走查

用浏览器自动化能力（`agent-browser` / `playwright-cli`）执行：

| 检查项 | 做法 |
|---|---|
| 页面加载 | 打开 `http://localhost:5173`，断言 canvas 存在 |
| 控制台干净 | 收集 console 与 pageerror，断言零 error |
| 首屏可玩 | 截图，确认开始界面正常渲染 |
| 玩法可用 | **在 canvas 内模拟真实鼠标事件**（`page.mouse.move/down/up`），触发核心操作 |
| 状态迁移 | 断言从 Ready → Playing → GameOver 的状态变化（读取暴露的调试变量或截图比对） |
| 重开可用 | 模拟点击重开按钮，断言回到 Ready |
| 移动端视口 | 设 `375×667` 视口重跑一遍，截图确认布局正常 |

**注意**：Phaser 的 canvas 内元素无法用普通 DOM 选择器点击，必须用坐标级鼠标事件。若无法断言内部状态，在开发构建中暴露一个只读的 `window.__gameState` 供测试读取（生产构建剔除）。

### 3. 生成报告

输出 `docs/07-qa/report.html`：每项检查的通过状态、失败项的截图、控制台日志摘要。

### 4. 生成试玩链接

用「发布为应用」能力把 `dist/crazygames/` 发布为在线链接。

**用途**：
- Poki 提报要求「无需登录即可访问的可玩构建链接」
- 自己快速验证不同设备上的表现

### 5. 校验

```bash
python <skill>/scripts/gate_check.py --project <project> --stage qa
```

## 自检

- [ ] 页面加载无报错，canvas 正常渲染
- [ ] 控制台零 error（含未捕获异常）
- [ ] canvas 内点击可触发核心玩法
- [ ] 状态迁移正确：Ready → Playing → GameOver → Ready
- [ ] 移动端视口（375×667）布局正常
- [ ] `report.html` 已产出
- [ ] 试玩链接可访问

## 阻断性缺陷处理

以下任一情况视为阻断，必须回退修复后重跑：

- 控制台出现未捕获异常
- 玩法无法进行（操作无响应）
- 状态卡死无法回到 Ready
- 移动端布局错乱导致不可玩

连续 3 次失败 → 停止并上报。
