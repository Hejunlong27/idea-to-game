# 10b · Playtest Agent（自动试玩）

**目标**：让 Agent **真的去玩**生成的游戏，而不是只读代码和断言。
**前置**：游戏暴露 `window.__gameState` / `window.__gameEvents`（约定见 `references/game-event-schema.md`）。

## 为什么需要它

`shots.mjs` 只截图，`test-standalone.mjs` 只冒烟。两者都发现不了：
「玩家不知道按哪个键」「第三关卡住出不去」「连续 40 秒没有任何反馈」。

## 四种玩家策略

| 策略 | 行为特征 | 检查什么 |
|---|---|---|
| `novice` | 操作慢、频繁确认 | 操作是否容易理解 |
| `explorer` | 到处试、触发边角 | 可探索内容与隐藏反馈 |
| `strategist` | 少操作、按目标推进 | 机制互动与最优策略 |
| `extreme` | 高频乱按 | 漏洞与异常状态 |

游戏可以实现 `window.__bot.act(strategy)` 提供**自己的**操作策略（本作实现了 BFS 寻路 + 记忆管理），
没有就退回通用输入（随机点击 + 方向键 + 空格）。

## 采集内容

每 120ms 采样一次：

- `window.__gameState` 快照（用于检测卡死、状态演进）
- `window.__gameEvents` 新增事件（用于统计事件分布、首次正反馈时间）
- `pageerror` / `console.error`（运行时错误）
- 每 25 步一张截图

## 判定

| 项 | 阈值 |
|---|---|
| 卡死 | 连续 6 秒状态不变 |
| 首次正反馈 | ≤30s |
| 重复动作占比 | <70% |
| 运行时错误 | 0 |

## 运行

```bash
# 一键（起服务 + 跑 + 出 HTML 报告）
python scripts/playtest.py --project . --seconds 45

# 只重出报告
python scripts/playtest.py --project . --no-run
```

产物：
- `docs/07-qa/playtest.json`（机读）
- `docs/07-qa/playtest-shots/*.png`（截图）
- `docs/07-qa/playtest-report.html`（人读，**三类结论分开列**）

## 报告的三种结论必须分开

任务书要求区分「程序检测结果」「AI 评价」「人工评价」，报告里是三节：

1. **程序检测结果**（客观）：时长、操作数、事件数、卡死、错误、首次正反馈 —— 这些是测出来的
2. **AI 评价**（启发式）：基于规则（事件密度、重复率、空闲间隔）的推断，**不是审美判断**
3. **待人工确认**（AI 无法判定）：操作是否「一看就懂」、难度曲线是否合适、
   「值得记住的瞬间」是否成立

**AI 模拟试玩不等于真实用户测试。** 每个报告头部都有这句声明，审核会检查它存在。

## 固定随机种子

`playtest.mjs` 的输入策略按步数取模（不用 `Math.random` 决定关键分支），
游戏侧的事件时间戳来自场景时钟 —— 保证同一版本两次试玩的行为可比。

## 与其它测试的分工

| 脚本 | 速度 | 检查什么 |
|---|---|---|
| `smoke.mjs` | 10s | 闭环能不能走通 + 截图 |
| `qa.mjs` | 40s | 断言 + 帧率（含基线对照）+ 移动端视口 |
| `playtest.mjs` | 40–60s × 4 策略 | 真实操作策略下的体验问题 |

交付前三个都要跑。CI 里只跑 smoke。
