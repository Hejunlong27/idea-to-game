# 动效设计

## 为什么动效必须「设计」而不是「加特效」

程序化特效解决的是「有没有反馈」，动效设计解决的是「反馈对不对」。

两者的差别：

| | 加特效（现状） | 动效设计 |
|---|---|---|
| 判据 | 有碎片、有闪光 | 时机、力度、节奏、曲线都调过 |
| 结果 | 热闹但轻飘 | 有重量、有节奏、有冲击 |

**「爽感不够」的技术原因往往不是特效太少，是关键的那一下没做对。**

---

## 一、撞击感的核心是顿帧，不是粒子

**这是最重要的一条。**

打击的瞬间让画面**冻结 30–80ms**，比加一百个粒子都有效。这是格斗游戏二十年验证过的技术
（hit stop / hit freeze），但塔防几乎没人用。

为什么有效：人眼对「运动突然停止」极其敏感，这一停会在大脑里被解读成「撞到了硬东西」。
而粒子飞散只传达「有东西碎了」，不传达「撞得多重」。

### 参数

| 事件 | 顿帧时长 | 理由 |
|---|---|---|
| 普通击杀 | 40ms | 刚好能感知，不打断节奏 |
| 精英击杀（甲兽） | 80ms | 越重越久 |
| 漏怪（基地受损） | 60ms | 比击杀更「钝」 |
| 塔升级 | 50ms | 强调「变强了」 |

### 实现约束（关键）

**只缩放 `tweens.timeScale`，绝不改 `time.timeScale`。**

后者会改变 `delta`，进而破坏玩法的确定性（测试会失败、回放会不一致）。
前者只影响表现层，逻辑时钟照常走。

```ts
private hitStop(ms: number) {
  this.tweens.timeScale = 0.02;          // 表现几乎冻结
  this.time.delayedCall(ms, () => {      // 用游戏计时器恢复，不受 tween 影响
    this.tweens.timeScale = 1;
  });
}
```

## 二、缓动曲线是「性格」

不同的 ease 传达不同的物理感。**用错 ease 比没有动效更糟**——会让玩家觉得「怪」。

| 事件 | ease | 为什么 |
|---|---|---|
| 建塔 | `Back.easeOut` | 弹一下再稳住 = 有体积、有重量 |
| 击杀碎片 | `Quad.easeOut` | 快速冲出后减速 = 空气阻力 |
| 金币飞向 HUD | 先 `Quad.easeOut` 上抛，再 `Cubic.easeIn` 加速下落 | 抛物线 = 重力 |
| 连杀文字 | `Quad.easeOut` 上浮 | 轻、快、不抢戏 |
| 漏怪震屏 | 线性 + 快速衰减 | 冲击是瞬时的，不能有回弹 |
| 波次清空 | `Quad.easeIn` 收回 | 慢收尾 = 喘息 |

**一条经验**：**「出现」用 Back/Elastic（有弹性），「消失」用 Quad/Cubic（干脆）。**
反过来会显得拖泥带水。

## 三、节奏比强度重要

一直高能 = 没有高能。玩家会疲劳。

正确的节奏结构（以一波为例）：

```
准备期（低）→ 接敌（升）→ 密集击杀（高）→ 波次清空（顿+光晕，释放）→ 短暂低谷
```

**每一波必须有一个「释放点」**（波次清空的光晕 + 缩放脉冲就是干这个的）。
没有释放点，玩家只会觉得「累」而不是「爽」。

---

## 四、震动要有方向和层次

`camera.shake(duration, intensity)` 的两个参数不是随便填的：

| 事件 | 时长 | 强度 | 意图 |
|---|---|---|---|
| 普通击杀 | 60ms | 0.0022 | 只是「碰了一下」 |
| 精英击杀 | 90ms | 0.004 | 「有点重」 |
| 漏怪 | 120ms | 0.006 | 「你被打了」 |
| 通关 | 200ms | 0.008 | 「大地震」 |

**关键：弱事件不要用强震。** 如果每个击杀都震 0.006，玩家两分钟就麻了，
真正重要的「漏怪」反而没感觉。

---

## 五、动效设计表（产物）

每个项目应该有一张表，写清楚「什么事件 → 什么动效 → 什么参数」：

```json
{
  "hitStop": { "kill": 40, "killElite": 80, "leak": 60, "upgrade": 50 },
  "ease": { "build": "Back.easeOut", "burst": "Quad.easeOut", "coinUp": "Quad.easeOut", "coinDown": "Cubic.easeIn" },
  "shake": { "kill": 0.0022, "killElite": 0.004, "leak": 0.006, "win": 0.008 },
  "duration": { "muzzle": 110, "spark": 140, "burst": 260, "combo": 620, "waveClear": 600 }
}
```

这张表和 `visual-dna.json` 同级重要——**一个是静态语言，一个是动态语言**。

## 六、L0.5 应该包含「动效 demo」

静态 mockup 只能看「长什么样」，看不出「动起来爽不爽」。

所以 L0.5 的交付物应该是两样：

| 产物 | 看什么 |
|---|---|
| 静态 mockup（一屏画面） | 构图、配色、风格统一 |
| **动效 demo（5–10 秒录屏）** | **节奏、撞击感、缓动是否对** |

录屏内容：建塔 → 接敌 → 密集击杀（含连杀）→ 漏怪 → 波次清空。
这一段能暴露「爽不爽」的全部问题，比一百张静态图有用。

## 七、判据：怎么知道动效做对了

不能靠「感觉」。三个可观察的信号：

| 信号 | 说明 |
|---|---|
| **能感到「重量」** | 击杀时画面一顿，玩家身体会有轻微反馈 |
| **节奏有起伏** | 不是一直吵，有紧张也有喘息 |
| **关掉音效能玩** | 纯视觉也能分辨「打中了 / 漏了」—— 说明动效信息量够 |

第三条是硬指标：**如果关掉声音就分不清发生什么，说明动效没承担起信息传达的责任。**
