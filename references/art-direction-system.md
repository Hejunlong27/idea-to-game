# 美术驱动体系

## 先说结论

试玩反馈里「玩法太大众、美术不吸引人、不会下载」是**战略级问题**，不是执行问题。

玩法创新确实难，把竞争力押在美术上是合理的。但**美术驱动有个陷阱必须先避开**：

> 美术决定「进不进来」，玩法决定「留不留下来」。
> 只做美术，会得到「点进来三秒就退」的结果。

所以这套体系不是「只做美术」，是**用美术抢注意力，用反馈密度留住人**。两层必须一起做。

---

## 一、五个必须先纠正的认知

### 1. 「爽感不够」不是美术问题，是反馈密度问题

你说第 2 点「全程无聊、爽感不够」——这个和美术风格几乎无关。塔防现在的反馈缺口：

| 事件 | 现在 | 应该有 |
|---|---|---|
| 敌人被击杀 | 缩放 + 一个音效 | 碎片飞散 + 短促震屏 + 金币飞向 HUD + 连杀计数 |
| 塔开火 | 一条细线 | 枪口闪光 + 后坐力 + 弹壳 + 命中点火花 |
| 塔升级 | 一个飘字 | 光柱升起 + 底座扩散环 + 属性数字跳动 |
| 漏怪 | 震屏 | 屏幕红闪 + 基地裂纹 + 低频轰鸣 |
| 波次清空 | 无 | 短暂停帧 + 全屏光晕 + 金币雨 |

**这些是「游戏手感」的标准配置，跟美术风格无关。** 换成再好的画，缺这些照样无聊。

### 2. 短剧风格不能直接搬，要做「游戏化改造」

RHSTORY 的 306 条是给**短剧**的——追求氛围层次。游戏需要的是**信息对比**。

三个硬测试，任何素材过不了就不能用：

| 测试 | 方法 | 不过说明什么 |
|---|---|---|
| **剪影测试** | 把图全黑只看轮廓 | 认不出是什么 → 形状设计失败 |
| **缩小测试** | 缩到 84px（一格大小） | 看不清 → 细节密度过高 |
| **去色测试** | 转灰度 | 分不清敌我 → 明度对比不足 |

短剧风格天然偏「细节丰富、层次柔和」，这三项经常全挂。所以要从 **2D 组（157 条）** 选，且必须加游戏化约束。

**真人组（86 条）基本不能用**：写实人脸在 84px 下是一坨糊，而且真人脸做敌人很怪。

### 3. 视频素材在游戏内是坑

你提到「视频素材生成」。要分清两件事：

| 用途 | 是否适合视频 |
|---|---|
| 商店预告片 / 开场动画 | ✅ 适合 |
| 游戏内单位/特效 | ❌ 不适合 |

游戏内用视频的问题：1 秒 720p ≈ 200KB–1MB，十个就爆预算；无法响应交互（塔防要即时反馈）；无法无缝循环；移动端解码耗电。

**游戏内用序列帧（4–8 帧）或程序化动效**，视频只投在商店素材。

### 4. 一致性是最大成本，也最容易翻车

同一个角色生成 10 次会有 10 个样。这是 AI 美术落地最大的坑，不是「生成得好不好看」的问题。

**实测数据（见第四节）**：纯 t2i 有 29% 的样本对「像不同角色」，主因是姿态漂移而配色稳定。

三种解法，按成本排：

| 方案 | 做法 | 实测效果 | 代价 |
|---|---|---|---|
| 降低细节依赖 | 角色做到「图标级」，不做特写 | 未测 | 表现力受限，但最稳 |
| 设定图做 ref | 先生成一张标准像，后续 i2i | **IoU 1.0，但几乎是复制** | 需调 denoise 才能出变体 |
| ControlNet 锁姿态 | 用骨架约束 | 未测 | 需要额外工作流 |

**建议：游戏内单位走「图标级 + 设定图 ref + 适度 denoise」，只有主角/关键角色才做特写。**

**铺开前必须跑 `consistency_check.py`**，用数据判断而不是肉眼看。

### 5. 商店素材是独立的一套，不是游戏内素材

游戏内素材 ≠ 商店截图。商店需要三样，现在一样都没有：

| 素材 | 要求 |
|---|---|
| 图标 | 512×512，缩到 128px 还能认出是什么游戏 |
| 截图 | 3–5 张，必须含 UI 和动作瞬间（不能是空场景） |
| 预告片 | 15–30 秒，**前 3 秒必须有钩子** |

## 二、六层架构

你的三层（风格基调 → 素材设计 → AI 生成）是对的，我补三层（美学 demo、动效反馈、商店素材）。

```
L0   风格锚定     ← 从 RHSTORY 选 + 游戏化改造 + 三测试
      ↓
L0.5 美学 demo    ← 【门禁】一屏完整观感，定「这游戏长什么样」
      ↓
L1   素材设计     ← 角色/场景/道具，各自专属提示词框架
      ↓
L2   AI 生成      ← ComfyUI 本地 / 闭源模型，分层调度
      ↓
L3   动效与反馈   ← 序列帧 + 程序化特效（解决「爽感」）
      ↓
L4   商店素材     ← 图标/截图/预告片（决定点击率）
```

### L0.5 美学 demo 实测（2026-11-09）

生成 3 个敌人 + 2 座塔，按**游戏真实布局**（720×1280、84px 网格、关卡 1 真实路径）拼成一屏。

**结果：素材方向对了，但暴露了背景是短板。**

| 项 | 评价 |
|---|---|
| 素材剪影 | ✅ 三种敌人可分辨（青绿小妖 / 黄色疾影 / 紫甲兽） |
| 塔的辨识 | ✅ 青水晶塔 vs 橙炮塔，一眼区分 |
| 光源一致 | ✅ 都是左上 |
| 风格统一（素材之间） | ✅ 赛璐璐 + 粗描边，同源 |
| **素材 vs 背景** | ❌ **明显「两张皮」** |
| 360px 手机尺寸 | ✅ 仍可分辨、文字可读 |

**「两张皮」的具体表现**：素材有粗描边和明确色块，背景是纯程序化深色网格——
对比强烈，像贴纸贴在深色板上。缩到 360px 后更明显。

### 所以铁律从三条变四条

原本定的是色阶/光源/描边三条。实测后必须加第四条：

| # | 铁律 | demo 定的值 |
|---|---|---|
| 1 | 色阶数量 | 5 阶 |
| 2 | 光源方向 | 左上单光源 |
| 3 | 描边策略 | 统一粗描边（1024px 下约 3px） |
| 4 | **背景必须同风格** | **不能留程序化**，必须同描边同色阶 |

第 4 条是这次 demo 最重要的产出——**背景是画面的 80%，它不跟上，素材再好也像贴纸。**

### 背景迭代三版：为什么「背景要弱」

第一版（纯程序化色块）→ 两张皮，像贴纸贴深色板。
第二版（直接贴 AI 纹理）→ **更差**：纹理是「小瓷砖」质感，缩到 84px 后变成密集网格，
视觉噪音比素材还强，把主体压住了。
第三版（模糊 + 降对比 + 压暗 + 统一色调）→ **对了**：背景退到后面，素材成为视觉重点。

| 版本 | 背景处理 | 观感 |
|---|---|---|
| v1 | 纯色 | 两张皮 |
| v2 | 直接贴纹理 | **噪音压过主体** |
| v3 | 模糊 2.2px + 对比 0.45 + 亮度 0.72 + 色调融合 45% | **衬托到位** |

**核心原则：背景的职责是衬托，不是表现。**

判断标准：把画面缩到 360px，**第一眼看到的是敌人还是地面**？
看到地面就是背景过强了。

具体参数（`art_mockup.py` 的 `prep()`）：

```python
blur=2.2          # 消除小格子噪音
contrast=0.45     # 降到不足一半
bright=0.72       # 压暗
tint_blend=0.45   # 向目标色调融合，保证地面/路面同一套色
```

### 对素材清单的影响

原来打算「单位用 AI、背景用程序化（可控可平铺）」。实测证明这个分工是错的：

| 原计划 | 修正后 |
|---|---|
| 单位 AI、背景程序化 | **单位 AI、背景也 AI**（程序化只做 UI 层和特效） |

理由：程序化背景能做到「可平铺、可控」，但做不到「和赛璐璐素材同一套语言」。
背景要么整体 AI 化，要么用「程序化底 + AI 纹理叠加」两层。

### L0.5 美学 demo（为什么必须有这一层）

**单个素材好看 ≠ 游戏好看。** 这是 AI 美术落地最常见的翻车点：
每个角色单独看都不错，拼到一屏里却「各画各的」——光源不一致、色阶不统一、细节密度打架。

所以必须在拆素材之前，先出**一屏完整画面**：

| 要素 | 要求 |
|---|---|
| 内容 | 背景 + 3–5 个敌人 + 2–3 座塔 + 弹道 + UI 框 + 特效 |
| 形式 | 一张 mockup 图（AI 生成或手工拼），不做交互 |
| 验收 | ① 缩到手机尺寸还看得清 ② 三秒内能认出是什么游戏 ③ 各元素光源/色阶一致 |

**demo 不过关不进 L1。** 理由：改一张 mockup 的成本是一小时，改全套素材的成本是一周。

**demo 阶段必须定死的四条铁律**（实测后从三条加到四条）：

1. **色阶数量** —— 决定细节密度上限
2. **光源方向** —— 决定所有素材的高光位置
3. **描边策略** —— 决定缩小后的可读性
4. **背景风格** —— 必须与素材同描边同色阶，否则像贴纸（这条是实测补的）

这四条写进 `visual-dna.json` 的 `adaptations`，后面每个素材生成都要带上。

### L0 风格锚定

产出 `docs/02-art/visual-dna.json`：

```json
{
  "anchor": { "source": "rhstory:2d/003", "name": "日式赛璐璐" },
  "adaptations": ["轮廓加粗 2px", "色块压缩到 5 阶", "统一左上光源"],
  "tests": { "silhouette": "pass", "shrink_84px": "pass", "grayscale": "pass" },
  "palette": { "bg": "#0E1B2A", "ally": "#4A8A8C", "enemy": "#C1443C", "accent": "#F2C14A" }
}
```

**关键**：`adaptations` 是游戏化改造项，不是原样照搬。`tests` 三项必须全 pass 才进入 L1。

### L1 素材设计

四个角色，各自有专属提示词框架（不是一个大 prompt 打天下）：

| 角色 | 负责 | 提示词框架要点 |
|---|---|---|
| 美术总监 | 风格一致性、三测试把关 | 只做判断不生成，输出 `visual-dna.json` |
| 角色设计师 | 单位/敌人/主角 | 剪影优先、姿态清单、状态变体（正常/受击/死亡） |
| 场景设计师 | 地图/背景 | 俯视视角、留出 UI 安全区、可平铺 |
| 道具设计师 | 塔/子弹/图标 | 正投影、可旋转、与角色同一光源 |

产出 `docs/02-art/asset-spec.json`（已有结构，补 `silhouette`/`states` 字段）。

### L2 AI 生成

分层调度，控成本：

| 阶段 | 通道 | 理由 |
|---|---|---|
| 草稿探索（多方案比稿） | ComfyUI 本地 | 免费，允许浪费 |
| 定型精修 | 闭源模型 | 一致性更好 |
| 批量变体（状态/帧） | ComfyUI + i2i ref | 锁定同一角色 |

### L3 动效与反馈

这是「爽感」的落点。实现分三种：

| 类型 | 做法 | 成本 |
|---|---|---|
| 程序化特效 | Phaser Graphics + tween | 几乎为零，优先用 |
| 序列帧 | 4–8 帧 PNG | 中等 |
| 视频 | 只用于开场 | 高，慎用 |

**已实现（`src/game/fx.ts`，塔防）**：

| 事件 | 反馈组合 | 时长 |
|---|---|---|
| 击杀 | 碎片飞散 + 短震屏 + 连杀计数 + 金币飞向 HUD | 260–620ms |
| 塔开火 | 枪口闪光 + 命中火花 + 弹道线 | 110–140ms |
| 塔升级 | 光柱升起 + 扩散环 + 数字跳动 | 380–420ms |
| 漏怪 | 全屏红闪 + 震屏 + 低频音 | 180ms |
| 波次清空 | 相机缩放脉冲 + 中央文字 | 180+420ms |

**三条实现约定**：

1. **全部程序化**。特效是即时反馈，起效时间要精确到毫秒；序列帧做不到，且 10 组图体积不可控。
2. **必须限流**。单次爆发粒子 ≤14，全局存活 ≤120，否则低端机掉帧。
3. **尊重 `prefers-reduced-motion`**。开启时降级为「只有数字，无粒子」。

**截图抓不到瞬时特效**（<300ms），验证要靠真机玩或录屏，不能靠静态截图。

### L4 商店素材

独立产出，不复用游戏内素材。图标/截图/预告片三件套。

## 三、落地顺序（重要）

**不要一次把六层全做完。** 正确顺序是：

1. **先补反馈密度**（L3）—— 成本最低、对「爽感」提升最直接，一天能做完
2. **再定风格锚点**（L0）—— 选 3 个候选各生成 1 张，用三测试筛
3. **然后出美学 demo**（L0.5）—— 一屏完整观感，定色阶/光源/描边三条铁律
4. **单点突破**（L1+L2）—— 只做一个敌人 + 一座塔，接进游戏看真实效果
5. **验证一致性**（L2）—— 同一角色生成 10 次，看差异能不能接受
6. **验证有效再铺开** —— 全量素材是最贵的一步，不能赌

理由：如果先铺全量美术，做完发现「还是无聊」，沉没成本最高。
**一致性没验证就铺开，等于赌博。**

## 四、实测验证（2026-11-09）

按上面流程跑了第一轮最小验证：**赛璐璐 + 游戏化约束 → 生成 1 个敌人 + 1 座塔 → 84px 缩图测试**。

### 生成参数

| 项 | 值 |
|---|---|
| 通道 | ComfyUI 本地（qwen_image_2.1_turbo_int8） |
| 耗时 | 1024² 约 45 秒/张，两张批量 49 秒 |
| 提示词要点 | `thick black outline` / `flat color blocks only 5 tones` / `single top-left light source` / `simple readable silhouette` / `plain solid light gray background` / `no shadow, no gradient` |

### 三测试结果

| 测试 | 敌人 | 塔 |
|---|---|---|
| 剪影（全黑能认出） | ✅ 角+大眼+小身，一眼是怪物 | ✅ 塔形+水晶，一眼是塔 |
| 缩小 84px | ✅ 角、琥珀眼仍清晰 | ✅ 水晶醒目，石材未糊 |
| 去色对比 | ✅ 深青 vs 浅灰底，明度差足够 | ✅ 石材 vs 水晶，对比强 |

**结论：赛璐璐 + 粗描边这条路在 84px 下成立**，可以铺开。

### 关键提示词经验

1. **`thick black outline` 是最重要的一条**。没有它，赛璐璐会退化成厚涂，缩小后糊成一团。
2. **`flat color blocks only 5 tones`** 强制压缩色阶，防止模型加渐变。
3. **`plain solid light gray background` + `no shadow, no gradient`** —— 浅灰背景方便阈值抠图（深色背景会吃掉深色主体，这是踩过的坑）。
4. **`simple readable silhouette`** 比任何「画得好看」的描述都管用。

### 一致性验证（2026-11-09，已做）

同一提示词跑两组，量化对比：

| 指标 | 纯 t2i（10 张 / 45 对） | 带 ref 的 i2i（5 张 / 10 对） |
|---|---|---|
| pHash 距离 | 17.1 / 128 | **2.4** |
| 剪影 IoU | 0.70 | **1.00** |
| 主色距离 | 11.7 | 5.9 |
| 「几乎相同」占比 | 13% | **100%** |
| 「像不同角色」占比 | **29%** | 0% |

**两个结论，都重要：**

1. **纯 t2i 不可用于量产**。29% 的样本对看起来像不同角色——主因是姿态漂移
   （prompt 写 `floating pose`，实际生成了站立），而配色几乎不变（主色距离 11.7）。
   **配色能锁住，形状锁不住。**

2. **i2i 能锁一致性，但当前参数下几乎是复制**。IoU 1.0 说明剪影完全重合，
   意味着它生成不了「同一角色的不同姿态」——只能做同一张图的微调。

**所以量产的正确姿势是**：i2i + 适度 denoise（0.4–0.6）或 ControlNet，
在「保持一致」和「允许变体」之间取平衡。当前工作流（SamplerCustom + ManualSigmas）
的 denoise 是固定的，需要另配。

**这次验证的最大价值是避免了「先铺开再发现不一致」** —— 那会白做全套素材。

### i2i denoise 调参：这条路走不通（已实测）

试着用截断 `ManualSigmas` 序列来控制 denoise 强度（d100 完整 / d85 截到 0.845 / d70 截到 0.704）：

| 档位 | 与 ref 距离 | 剪影 IoU | 结果 |
|---|---|---|---|
| d100（完整） | 3 | 0.998 | 复制 |
| d85 | 59 | **0.141** | **崩坏** |
| d70 | 59 | **0.141** | **崩坏** |

**为什么崩**：`SamplerCustom` 的 `add_noise: true` 会用起始 sigma 加噪。
sigma < 1.0 时加的噪声**不足以重建、但足够毁掉原图**，输出直接崩成噪点。

**更根本的原因**：这套工作流的 `492 ComfySwitchNode` 默认走 `EmptyLatentImage`，
即 **「带参考图的 t2i」而不是传统 i2i**。参考图通过 `images.image_1/2` 作为条件输入，
强度由 Qwen-Image-Edit 内部决定，**没有暴露可调参数**。

### 所以量产的正确姿势

不要指望「一个工作流搞定所有情况」。按用途分工：

| 用途 | 做法 | 为什么 |
|---|---|---|
| **定基础像**（角色标准照） | t2i，多试几次选最好 | 一次性投入，值得多跑 |
| **同姿态微调**（受击/死亡/换色） | i2i（当前工作流），接受「接近复制」 | 结构不变正是需要的 |
| **姿态变化**（站立/浮空/攻击） | t2i 重生成 + **严格姿态 prompt** + 多试选最像 | 一致性靠 prompt 和筛选，不靠 ref |

**关键认知**：一致性不是「一个参数能调的」，是**分场景用不同手段**。

对「姿态漂移」最有效的不是 ref，是**把姿态写死在 prompt 里**（`floating pose, feet off ground, no legs visible` 这种），
再靠多试筛选。

### 待验证

- **接入游戏**：抠图 → 缩放 → 替换程序化纹理，看实际观感
- **状态变体**：受击/死亡帧（走 i2i，结构不变正合适）
- **严格姿态 prompt 的效果**：能否把 t2i 的姿态漂移压到可接受

## 五、我的判断

**这件事值得做，但别指望「美术好 = 游戏好」。**

真实的因果关系是：

```
美术好 → 有人点进来（点击率）
反馈好 → 有人玩下去（留存）
玩法好 → 有人推荐（传播）
```

三件事缺一不可，但**顺序不能反**。现在这个塔防：美术是 0 分，反馈是 3 分，玩法是 6 分。

所以最该先动的其实是**反馈**（0→7 分的成本最低），美术是并行的长线投入。

你说「所有都要改」是对的，但改的顺序决定了什么时候能看到效果。
