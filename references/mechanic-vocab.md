# 机制词库 · 使用指南

> 数据在 `assets/data/mechanic-vocab.json`（48 个机制，10 类）。
> **新增机制只改 JSON**，`content_forge.py --analyze` 会自动匹配。

---

## 1. 怎么用

```bash
# 从一句话想法里匹配候选机制（按品类 + 动词）
python scripts/content_forge.py --idea "做个守灯塔的小游戏" --analyze

# 输出：推荐品类 / 匹配到的机制池 / 建议的咬合组合 / 每关节奏草案
```

`analyze` 只给**候选**，最终选择必须由 Agent 或人决定。脚本不替你设计。

## 2. 十类概览

| cat | 中文 | 解决什么 | 典型机制 |
|---|---|---|---|
| `input` | 输入动作 | 玩家怎么操作 | 点选、精度瞄准、拖放、划动、蓄力、路线取舍 |
| `space` | 空间地形 | 位置为什么重要 | 网格、多道、地形变化、重力、物理、高度分层 |
| `time` | 时间节奏 | 什么时候做 | 倒计时、节奏同步、回合制、昼夜、连击、回退 |
| `resource` | 资源经济 | 什么稀缺 | 收支、风险回报、槽位有限、稀缺曲线、兑换市场 |
| `build` | 构筑成长 | 怎么变强 | 合成、协同、卡牌连锁、进化分支、配装 |
| `threat` | 威胁敌人 | 压力从哪来 | 逼近、意图预读、诱饵、属性克制、首领三阶段、生存需求 |
| `info` | 信息认知 | 知道多少 | 迷雾、信息隐藏、探查、模式学习、擦边奖励、评级 |
| `meta` | 局外系统 | 为什么再来一局 | 局内地图、跨局解锁、每日挑战、成就、幽灵回放 |
| `narrative` | 叙事交互 | 为什么在乎 | 叙事解锁、事件对白、过场、规则反转 |

## 3. 组合原则（这才是深度的来源）

### 原则一：一主两副

一个品类需要一个**主机制**（决定操作）+ 最多两个**副机制**（改写主机制的意义）。
超过三个，玩家学不会；少于两个，第三关之后没有新东西。

```
主：drag_place（拖放布塔）
副1：limited_slots（槽位有限）  → 迫使放弃
副2：day_night（昼夜切换）      → 同一布局白天黑夜价值不同
```

### 原则二：咬合必须是「乘法」不是「加法」

加法（坏）：`冰冻` 和 `分裂` 互不相干，玩家只是多记一个图标。
乘法（好）：`冰冻` × `分裂` = 冻住的敌人无法分裂 → 玩家自己发现"先冻再打"的连招。

检验方法：写下两个机制名，问「同时存在时，玩家的最优策略会改变吗」。不会 → 只是加法。

### 原则三：难度轴至少一条非数值

只加速/加量 = 假深度。非数值轴举例：

| 轴 | 从 → 到 | 玩家感受 |
|---|---|---|
| 信息可见度 | 全显示 → 部分隐藏 | 从执行变成推断 |
| 资源充裕度 | 够用 → 枯竭 | 从选择变成取舍 |
| 操作复杂度 | 单步 → 组合 | 从反应变成编排 |
| 环境稳定性 | 静态 → 会变 | 从记忆变成应变 |
| 失败代价 | 可重试 → 不可逆 | 从练习变成承诺 |

### 原则四：每关必须有取舍

一句话能写成「A 好但 B 坏」。写不出来就是没有决策，只是执行。

## 4. 反模式（v1 踩过的坑）

| 反模式 | 症状 | 修法 |
|---|---|---|
| **换皮机制** | 5 种敌人本质是同一种，只有分值和颜色不同 | 每种敌人必须改变**玩家的动作**，不只是数值 |
| **堆料** | 加了 10 个机制但都孤立 | 用原则二筛，砍掉不咬合的 |
| **隐藏规则** | 机制存在但游戏里没提示 | 首次出现必须有可见线索（图标/颜色/一句对白） |
| **难度=提速** | 第 6 关和第 1 关操作一样只是快 | 引入非数值轴 |
| **叙事与玩法脱钩** | 故事是贴上去的，删掉不影响玩 | 故事必须解释**规则为什么是这样** |

## 5. 品类 → 机制组合参考

| 品类 | 推荐主机制 | 常用副机制 | 为什么 |
|---|---|---|---|
| `whack` / `arcade` | `tap_target` | `combo_chain` `fake_target` `timer_pressure` | 操作极简，深度全在目标和连击 |
| `tower_defense` | `drag_place` | `limited_slots` `build_synergy` `day_night` | 布局即策略 |
| `merge` | `merge_combine` | `gravity_fall` `limited_slots` | 空间压力来自"放不下" |
| `puzzle` | `space_grid` | `terrain_change` `rewind_takeback` | 可试错才有解谜感 |
| `runner` | `lane_switch` | `swipe_gesture` `threat_pressure` `rhythm_sync` | 三道并行制造归属判断 |
| `card` / `roguelite` | `card_combo` | `enemy_intent` `run_map` `meta_unlock` | 组合 + 预读 + 重复可玩 |
| `management` / `idle` | `resource_econ` | `scarcity_curve` `exchange_market` | 机会成本即玩法 |
| `rhythm` | `rhythm_sync` | `pattern_learn` `music_layer` | 听觉即规则 |

**跨品类借机制是加分项**：塔防借 `rhythm_sync`（按拍放塔有加成）会立刻变新鲜。
但每借一个，要重新验一次「玩家学得会吗」。

## 6. 与丰富度门禁的对应

| 门禁条目 | 对应本文件 |
|---|---|
| M1 机制数量 ≥5 | §3 原则一：一主两副，多关叠加 |
| M2 机制咬合 | §3 原则二：乘法检验 |
| M3 非数值难度轴 ≥2 | §3 原则三：五轴表 |
| M4 每关有取舍 | §3 原则四 |
| M5 规则反转 | `world_rule_twist` + `terrain_change` |

写蓝图时，每个机制必须填 `interacts`（引用其他机制 id）—— 门禁会校验 id 是否真实存在且双向可达。
